
## Flow запроса POST /api/tasks/

Рассмотрим, как обрабатывается запрос на создание новой задачи.

1. **URL попадает в router**  
   В config/urls.py подключён DefaultRouter, который регистрирует TaskViewSet с префиксом 	asks.  
   Поэтому POST-запрос на /api/tasks/ направляется в соответствующий viewset.

2. **Router вызывает ViewSet**  
   TaskViewSet наследует ModelViewSet (из DRF). Этот класс автоматически предоставляет метод create(), который обрабатывает POST-запросы.

3. **ViewSet использует Serializer**  
   Внутри create() вызывается get_serializer(), который возвращает экземпляр TaskSerializer (указан в serializer_class).  
   В сериализатор передаются данные из equest.data.

4. **Serializer валидирует данные**  
   TaskSerializer (наследник ModelSerializer) проверяет:
   - наличие обязательных полей (	itle, project и т.д.)
   - корректность статуса (по choices в модели)
   - целостность внешних ключей (project должен существовать)
   Если валидация не проходит, выбрасывается исключение, и клиент получает ответ с кодом 400.

5. **Service выполняет бизнес-логику**  
   В текущей реализации бизнес-логика инкапсулирована внутри сериализатора.  
   Метод create() сериализатора вызывает perform_create(), который устанавливает created_at и другие поля.  
   При необходимости здесь можно добавить дополнительные проверки (например, проверка прав доступа) — для этого используется perform_create во viewset.

6. **Repository/ORM сохраняет данные**  
   Сериализатор вызывает .save(), который через Django ORM выполняет INSERT в таблицу pi_task.  
   Данные записываются в PostgreSQL.

7. **API возвращает response**  
   После успешного сохранения сериализатор возвращает объект Response с сериализованными данными созданной задачи и HTTP-статусом **201 Created**.

Этот стандартный flow используется во всех CRUD-операциях проекта.
